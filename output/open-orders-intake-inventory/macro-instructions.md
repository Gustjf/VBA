# Open Orders - Order Intake - Inventory Analysis: Excel Macro Instructions

Version 2.8 (2026-10-15). The macro turns the three Snowflake exports for **all MSAs** (Order Intake, Inventory by Month, Open Order) and a **size class workbook** (the master list of models and size classes) into the workbook "001. Open Orders - Order Intake - Inventory Analysis By MSA.xlsx", five tabs: a File Format tab that explains the layout and the rules, one **Order Intake** tab with every MSA's order lines (and, in its frozen top row, the total ordered quantity of the rows the filters show), one **Inventory by Month** tab with units in stock by MSA and the inventory lines, one **Open Orders by MSA** tab with the ordered quantity of the open orders by MSA and product type and a chart of it, and a Run Log. What took an afternoon of filtering, sorting and copy-pasting now takes one click. The report is expected to be built about once a year; nothing in the tool depends on how often it runs.

Version 2.0 applied the manager's feedback of 2026-10-12 (plan: `stronger-ai-implementation-plan.md`): all MSAs in one set of exports with an MSA column; a separate size class workbook as the master list; cancelled orders and skid-steer loaders kept in the report but hidden by default filters; rows grouped by size class, then order status, then date; one Order Intake tab and one Inventory by Month tab instead of a tab per city; no colours, a minimal professional style. The Config control panel and the "check the setup first, build nothing if something is wrong" behaviour are unchanged from 1.3.

Version 2.1 applies the owner's answers of 2026-10-12 to the open questions: the column that names the area is **MSA** in every export (it is an MSA, a metropolitan area such as Dallas-Fort Worth, not a city), so the report says MSA everywhere (column B of Order Intake, the inventory tables, the Run Log) and the setting is `MSAColumn` (auto-detect tries an MSA header first); CTL= and MX= are the sum of TOTAL for a month, any day in the month counting for that month (as built in 2.0); the order status order stands; ORGANIZATION_NAME and ORGANIZATION_CUSTOMER_NUMBER are now on the inventory tab (the last two detail columns, easy to remove later); the size class workbook is a local file that `SizeClassFile` points to. A 2.0 or 1.x Config sheet is upgraded in place.

Version 2.2 changes only the look, at the owner's request: the report now reads like a printed engineering report. Black and white, Cambria type, fully ruled tables with a bold header and a double rule under it, numbered table captions on File Format, one-line source notes, and a page setup for printing (landscape, one page wide, the report name and build date at the top of each page, the tab name and page number at the bottom). The data, the rows, the formulas and the Run Log are unchanged.

Version 2.3 makes the tables easier to read on screen and on paper: the header rows are bold on mid-grey with a medium rule above, and every second visible row is light grey. The banding is a conditional format that counts only visible rows, so it stays even whatever filter is set or cleared.

Version 2.4 brings colour back, at the owner's request (the grey version read as too sombre for the team), and removes the vertical lines to cut visual clutter: the header rows are bold white on green, the bands light green, UNMAPPED Size Class cells peach again and the month cell yellow again. Tables keep only horizontal rules.

Version 2.5 adds the **Open Orders by MSA** tab the owner asked for (plan: `open-orders-by-msa-tab-implementation-plan.md`): the orders whose ORDER_STATUS is ORDERED or Not yet processed, their ordered quantity summed by MSA and product type in a live SUMIFS table, and a clustered column chart of it (one bar per MSA in each product type group; SSL on the chart only with ShowSSL TRUE). File Format and the Run Log gain the matching rows and lines (Section 5.5a). Nothing else in the report changes, and there is no new Config setting.

Version 2.6 adds the **visible total** the owner asked for (2026-10-15), so the manager no longer selects column G and reads the status bar's Sum: the frozen title row of the Order Intake tab reads "Total sum of ordered Quantity of visible selection:" with the figure right after it, above the SUM(F.ORDERED_QUANTITY) column. It is a live `SUBTOTAL(109, ...)` over the whole column, so it changes with every filter the reader sets (MSA, then size class, or any other) and never counts hidden rows. The manager still filters by hand; only the adding up is automated. To make room, that tab's source note moves from D1 to H1. Nothing else changes, and there is no new Config setting (Section 5.3).

Version 2.7 makes the **size class workbook the only source of a size class** (the owner, 2026-10-15: the earlier rules were a workaround from before the size class sheet existed). The macro reads 17 classes in the three families the business uses: track loaders (CTL) `0<2000` to `3500&Over`, mini excavators (MX) `>00-01` to `>06-10`, and skid-steer loaders (SSL) `EX Small`, `Small Frame`, `Med Frame`, `Large Frame`. A model that is not in the workbook is UNMAPPED, whatever its product type or name. The tonnes rule for E-models, the `Over10` class and the rated-operating-capacity cross-check are gone; the workbook's class is never second-guessed. The File Format tab's Table 1 lists the three families, so the tables below it move down three rows. Nothing else changes, and there is no new Config setting (Section 5.4).

Version 2.8 lets the owner **change the size classes without touching the macro** (the owner, 2026-10-15): the allowed classes are the three tables on the size class workbook's **Set-up** tab (CTL size class, MX size class, SSL size class), the same tables that feed the workbook's Size Class drop-down. Add a class there and the next build accepts it; remove one and rows that still carry it are UNMAPPED. The report ranks the classes CTL, then MX, then SSL, top to bottom, and File Format Table 1 lists them, so the tables under it move when the number of classes changes. A size class file without a Set-up tab (an older copy, or one built by Copilot prompt P11) still works with the 17 classes of 2.7, built into the macro. The Run Log says which: "Size classes: 17 from the Set-up tab (CTL 6, MX 7, SSL 4)" or "Size classes: the 17 built into the macro (... has no Set-up tab)". There is no new Config setting (Section 5.4).

History: 1.2 turned Config into a control panel; 1.3 made the Config sheet the only way to build (only `ShowOpenOrdersReportConfig` appears in Alt+F8). 2.0 to 2.8 keep both.

## 2. One-time setup (about 5 minutes)

1. Open Excel. Create a new blank workbook and save it as **`Open Orders Report Builder.xlsm`** (type "Excel Macro-Enabled Workbook"). Keep it somewhere permanent. Do not put the macro in PERSONAL.XLSB: the Config sheet would be created in that hidden workbook.
2. Press **Alt+F11**, select `VBAProject (Open Orders Report Builder.xlsm)`, **File > Import File...**, pick `build-open-orders-report.bas`. A module `modOpenOrdersReport` appears.
3. **Debug > Compile VBAProject**. No message means it compiled. Close the editor (Alt+Q) and save.
4. Press **Alt+F8**, run **`ShowOpenOrdersReportConfig`** (the only macro in the list). It creates the **Config** sheet, the control panel:
   - **Settings table** (rows 2 to 10, Section 4). Only the yellow Value cells can be edited; TRUE/FALSE settings have drop-downs, InventoryMonth is checked as a date, each cell shows a hint when selected.
   - **Buttons** (row 12): **Build report**, **Check setup**, **Choose input folder...**, **Choose output folder...**, **Choose size class file...**.
   - **Last run box** (rows 14 to 19): the result of the last build or check (green fine, amber built or ready with items to look at, red not built), when, a link to the last report, the MSAs found, the details.
   - **If something goes wrong** (rows 21 to 26): blocked macros, a build that stops with a list, UNMAPPED size classes, a missing or wrong MSA, editing the sheet.
   - Protected **without a password** (Review > Unprotect Sheet to change it; run ShowOpenOrdersReportConfig afterwards to tidy and protect it).
5. Click **Choose size class file...** and pick the size class workbook `size-class-master.xlsx`. The owner's decision (2026-10-12) is to keep it **local** for now: copy it next to the builder, for example `C:\Temp\oo-test\size-class-master.xlsx`, and point `SizeClassFile` at that copy. (In the repository it is `output/open-orders-intake-inventory/size-class-master.xlsx`; after GitHub's Download ZIP into `C:\Temp` it is `C:\Temp\AI-main\output\open-orders-intake-inventory\size-class-master.xlsx`.) A SharePoint or OneDrive folder synced to the PC also works later (choose the file in File Explorer's synced folder, not a web address; an "online only" file must be kept on the device).
6. Save. If Excel shows "macros have been disabled", click **Enable Content**; if macros are blocked by policy, ask IT to trust the folder.

**Upgrading from 2.0 or 1.x:** in the VBA editor remove `modOpenOrdersReport` (no need to export), import the new `.bas`, compile, and run `ShowOpenOrdersReportConfig` once. It converts the Config sheet in place and the Last run box says so once. From 2.0: `CityColumn` becomes `MSAColumn` and every value is kept ("Upgraded to v2.8: CityColumn is now MSAColumn ..."). From 1.x: InputFolder, OutputFolder, OutputFileName and OpenAfterBuild are kept; `ShowCancelled` = NOT `DropCancelled`, `ShowSSL` = `IncludeSSL`, `InventoryMonth` = `InventorySnapshotDate`; `HeaderCountMode` and `InventoryHeaderRow` are dropped ("Upgraded to v2.8: ... set SizeClassFile."). Then set SizeClassFile. A 2.1 to 2.7 Config sheet works with 2.8 as it is (nothing to upgrade); its "What it does" column keeps the older ShowSSL wording, because that column is written only when the Config sheet is created or upgraded from 2.0 or 1.x (cosmetic; delete the Config sheet and run `ShowOpenOrdersReportConfig` to get the new text, then set the values again). The old **SizeClassMap** sheet is no longer used; Check setup reminds you that it can be deleted (copy any rows you added to it into the size class workbook first). A build or a button click on an old Config sheet upgrades it the same way.

## 2a. Handing the workbook to someone else

Hand over the finished `.xlsm`, not the `.bas`.

1. Do Section 2 yourself, set the folders and SizeClassFile (shared paths if possible), click **Check setup**, run one build so the Last run box shows a result.
2. Save and close the `.xlsm`; send it with this file, or put both on the shared drive.
3. **Blocked macros are the most common hand-over failure.** Office blocks macros in files from email, Teams or a download (the "Mark of the Web") and shows a red "Security Risk" bar. The receiver closes the file, right-clicks it in File Explorer > **Properties** > ticks **Unblock** > OK, reopens it and clicks **Enable Content**. A Trusted Location or a trusted network share does not need this.
4. What they do each run: export the three files into one folder, open the `.xlsm`, check the Config values (Section 3), **Check setup**, **Build report**, read the Last run box.
5. Keep your own copy of the `.bas`. If the `.xlsm` is damaged, Section 2 rebuilds it in five minutes; the values to retype are in Section 4.

## 3. Each run (about 1 minute)

1. Export the three Snowflake reports, **for all MSAs**, into **one folder**. A file's kind is the start of its name; anything after it is free text:

   ```
   Order Intake 2026.xlsx          (required)
   Inventory by Month 2026.xlsx    (optional)
   Open Orders 2026.xlsx           (optional: "Open Order" works too; read and logged only)
   ```

   Every file of a kind is read and merged (the Run Log lists each file with its rows, and Check setup warns when there is more than one, so a stray old export is noticed). `.xlsx`, `.xlsm` and `.xls` are read; save CSV exports as .xlsx first. Earlier reports (names starting with "001" or containing "Analysis By MSA") and Excel lock files (`~$...`) are ignored, as is the size class workbook if it sits in the same folder. The old per-city layout (`Order Intake Austin.xlsx`, ...) still works: without an MSA column the MSA is taken from the file name.
2. On **Config**: `InputFolder` (Choose input folder..., or blank to be asked), `SizeClassFile`, `MSAColumn` (blank = found automatically; today's exports have a column headed MSA), `InventoryMonth` (blank = the latest month in the inventory file; any day in a month picks that month), `ShowCancelled` and `ShowSSL` (FALSE = hidden behind the filters).
3. Click **Check setup** (optional but quick). It reads the files, so it can list the MSAs and the inventory months found, and says "Ready to build" or lists what to fix. Warnings that do not stop a build include: two files of one kind, rows with a blank MSA, size class file rows it skipped, and **models in Order Intake that are not in the size class file** ("Models in Order Intake that are not in the size class file (UNMAPPED until added): ...", so you can add them to the master list before building).
4. Click **Build report**. Every build first runs the same check and stops **before creating anything** if something is wrong, with one list of what to fix (also in the Last run box). Otherwise the status bar shows progress, a message reports the time, the file, the MSAs and the inventory month, and the report opens. If a report with the same name exists you are asked before it is overwritten (No = a time-stamped copy); if it is open with unsaved changes the run stops.
5. Read the **Last run box** and the **Run Log** tab. If a model is **UNMAPPED** (Size Class bold on peach, listed in the Run Log), add it with its size class to the size class workbook, save it, and build again; UNMAPPED is the only state of a model the workbook does not list. The **Open Orders by MSA** tab shows the open orders chart (ordered quantity of orders ORDERED or Not yet processed, by product type and MSA); SSL is on it only with ShowSSL TRUE, though its table always has the SSL column.
6. **To count ordered units for a selection**, filter the Order Intake tab (for example MSA, then Size Class) and read the figure at the top, after "Total sum of ordered Quantity of visible selection:" (G1). It adds SUM(F.ORDERED_QUANTITY) over the rows the filters show, updates with every filter change, and stays in view while you scroll. No cells need selecting.
7. **To see hidden rows**, clear the filter on that column (the filter button > Clear Filter From ...): ORDER_STATUS for cancelled orders, PRODUCT_TYPE_ABBR for skid-steer loaders, on the Inventory tab Month and PRODUCT_TYPE. Nothing is ever deleted from the report for its status or type (only product types other than CTL, MX and SSL are left out, and counted in the Run Log).
8. Nothing is added by hand after a build (the manager's answer of 2026-10-12): distribute the file as built.

## 4. Config settings

| Setting | Default | Meaning |
|---|---|---|
| `InputFolder` | blank | Folder with the exports of all MSAs. Blank = a folder picker at build. |
| `OutputFolder` | blank | Where the report goes. Blank = InputFolder. |
| `OutputFileName` | `001. Open Orders - Order Intake - Inventory Analysis By MSA.xlsx` | .xlsx is added if missing. |
| `SizeClassFile` | blank | Full path of the size class workbook (the master list). **Required.** Choose size class file... fills it. Quotes around a pasted path ("Copy as path") are removed. |
| `MSAColumn` | blank | Header of the MSA column in the exports (MSA in today's exports). Blank = found automatically, an MSA header first (Section 5.2). When set, every export that is read must have it. |
| `InventoryMonth` | blank | Any day in the month the inventory tab shows, e.g. 8/1/2026. Blank = the latest month in the inventory file. |
| `ShowCancelled` | FALSE | FALSE hides cancelled orders behind the filter on ORDER_STATUS; TRUE shows them. They are in the report either way. |
| `ShowSSL` | FALSE | FALSE hides skid-steer loaders behind the filters on both tabs and leaves them off the Open Orders by MSA chart; TRUE shows them. |
| `OpenAfterBuild` | TRUE | Leave the finished report open. |

No value is silently replaced. A build stops, with a message naming the setting, when: a TRUE/FALSE setting holds anything other than TRUE, FALSE, YES, NO, Y, N, 1 or 0; InventoryMonth is not a date; OutputFileName contains `\ / : * ? " < > |`; a folder does not exist or the output folder cannot take a file; SizeClassFile is blank, missing, a web address, unreadable, or has no usable rows; MSAColumn is not a header of an export; a file has no MSA column and no MSA in its name; or there is no Order Intake file.

## 5. What the macro does with the data

### 5.1 Reading
- Each export's first sheet is read; the header row is the first row with at least three filled cells; columns are found by header name (order does not matter). Required: Order Intake `ORDER_DATE, REQUESTED_DATE, ORDER_STATUS, IS_OPEN_ORDER, SUM(F.ORDERED_QUANTITY), PRODUCT_TYPE_ABBR, MODEL_GROUP, MODEL_NUMBER, ORGANIZATION_NAME`; Inventory `PRODUCT_TYPE, MODEL_GROUP, MODEL_NUMBER, INVENTORY_DATE, TOTAL`. A file without them is skipped and named in the Run Log ("is missing column(s) ..."). The Open Order file feeds nothing; its rows and MSAs are counted in the Run Log (open question 3).
- Blank rows are ignored and counted: per file, rows read = written + dropped (other product types) + blank.
- Dates stored as text in ORDER_DATE, REQUESTED_DATE or INVENTORY_DATE are converted when they read as a date with a 4-digit year and a day (2026-08-05, Snowflake's 2026-08-05 00:00:00.000, 2026-08-05T00:00:00Z, 8/5/2026, Aug 5, 2026). Anything else (TBD, or a month without a day such as "August 2026") is left as it is, sorts last in its group, and its rows are listed in the Run Log. Text dates not in yyyy-mm-dd form are read in the PC's date order; on a PC not set to month-first dates the Run Log ends with a warning.
- Text that only looks like a number or a date (a MODEL_NUMBER such as 00123, a month such as "August 2026") stays text.

### 5.2 The MSA of a row
1. `MSAColumn` set: that header (ignoring case and outer spaces) in every export read, Open Order included; otherwise a problem naming the headers found.
2. Blank: the first header that equals `MSA`, contains `MSA`, equals `CITY`, contains `CITY`, `METRO` or `MARKET` (in that order of tests, ignoring case, spaces and underscores; MSA first since 2.1 because the real exports use it). Each file can use a different header (the test files use MSA and CITY); the Run Log says which ("MSA column MSA, 3 MSAs").
3. No MSA column: the MSA is the file name after the kind, up to the first underscore (`Order Intake Austin_2026-09.xlsx` is Austin). If that is empty too, the setup check stops with a problem.
4. MSA text is trimmed, runs of spaces collapsed and compared ignoring case; the first spelling read wins (Order Intake files first, alphabetically, then the inventory file). A blank MSA cell becomes **(no MSA)**, an MSA of its own (it sorts first), and the Run Log counts those rows.

### 5.3 Order Intake tab
- Keeps every row whose PRODUCT_TYPE_ABBR (trimmed, upper-cased) is CTL, MX or SSL, written trimmed and upper-cased; other types are dropped and counted per file. Nothing is dropped for its status.
- Columns: Size Class, MSA, then the nine export columns in their export order. Dates m/d/yyyy, quantity 0.
- **Hidden by default:** an AutoFilter on row 2 with ORDER_STATUS "does not equal CANCELLED" (unless ShowCancelled) and PRODUCT_TYPE_ABBR in {CTL, MX} (unless ShowSSL). Excel's filter ignores case but not stray spaces, so " CANCELLED " would stay visible (Snowflake does not pad statuses). The rows are in the file; clearing a filter shows them. After filtering, the macro checks every row against the rules; if Excel's filter hid other rows, it sets those rows directly and writes "WARNING: Excel's filters on the ... tab hid other rows than the rules ..." to the Run Log (please report it: the filter criterion then needs changing). The same check runs on the inventory tab.
- **Sort:** size class (the File Format order: the CTL classes, then the MX classes, then the SSL classes, then UNMAPPED last); inside a class order status: ORDERED, Not yet processed, INVOICED, Completely processed, any other status, CANCELLED (open orders first because the report is about open orders; cancelled last because they are hidden); then ORDER_DATE newest first (date part; rows without a date after the dated rows of their group); then MSA alphabetical; then export order (file order, then row order).
- **Visible total (v2.6)**, in the frozen title row: F1 reads `Total sum of ordered Quantity of visible selection:` (bold, right-aligned, so it runs left over D1 and E1, which stay empty) and G1, right after it and above the SUM(F.ORDERED_QUANTITY) column, holds `=SUBTOTAL(109,$G$3:$G$n)` over the whole column (bold, 12 point, `#,##0`, left-aligned so it reads on from the label). SUBTOTAL 109 adds only the rows that are not hidden, by a filter or by hand, so the figure is what a reader would get by selecting the visible G cells and reading the status bar's Sum. It follows any filter set or cleared after the build. With no rows it covers G3 alone and shows 0. A quantity that is not a number adds nothing. The row prints too, as part of the repeated header rows, so each printed page shows the total of the rows printed.
- H1 states the source, the number of files, the build date and which rows the filters hide (D1 on the other tabs; it moved to make room for the total).

### 5.4 Size classes and the size class workbook
- The master list is the first sheet of `SizeClassFile`. Columns by header name, ignoring case, spaces and underscores: **Name of machine** (`Name of machine`, `Machine`, `Model`, `MODEL_GROUP`) and **Size Class** (`Size Class`, `SIZE_CLASS`, `Class`). Other columns (HP, Rated Operating Capacity, Notes) are the owner's reference and are not read.
- **The allowed classes (v2.8)** come from the workbook's **Set-up** tab (any sheet named Set-up, ignoring case, spaces and hyphens): three tables, found anywhere on the tab by their headers `CTL size class`, `MX size class` and `SSL size class`. Each is read from the cell under its header down, CTL first, then MX, then SSL; that is the rank order of the report. Blank cells are skipped and text is trimmed. Warnings name the cell: a class listed again (in the same or another table, ignoring case; the first stays) and the word UNMAPPED (it marks models not in the file) are ignored. A missing header, an empty Set-up tab or more than 98 classes stop the build with a problem. Without a Set-up tab the macro uses the 17 classes of 2.7 (below).
- A row is used when it has a name and one of the allowed classes (spelled as on the Set-up tab, case does not matter: `ex small` is read as `EX Small`; no other spellings). Warnings name the row: no name, no class, a class that is not one of them (row skipped; `Over10` is no longer a class), a name listed again (the first row wins).
- Lookup: MODEL_GROUP (trimmed, upper-cased) equal to a name, else equal to a name's first word (so `T740 Compact Track Loader` matches T740).
- The 17 classes the Set-up tab of `size-class-master.xlsx` starts with, which are also the built-in ones, in report order, in three families (File Format Table 1): track loaders (CTL), by rated operating capacity in lb: `0<2000`, `2000<2300`, `2300<2600`, `2600<3000`, `3000<3500`, `3500&Over`; mini excavators (MX), by nominal tonnes: `>00-01`, `>01-02`, `>02-03`, `>03-04`, `>04-05`, `>05-06`, `>06-10`; skid-steer loaders (SSL), by frame size: `EX Small`, `Small Frame`, `Med Frame`, `Large Frame`. The class always comes from the workbook; the macro does not compute one, and does not check a class's family against PRODUCT_TYPE_ABBR.
- A model not in the list is **UNMAPPED**, with no exception (Size Class bold on peach, sorted last, in its MSA's Run Log line and the Last run box).
- `size-class-master.xlsx` (2026-10-15, replacing the 83-model starter): the 29 models of the owner's Bobcat Equipment Size Class sheet (11 CTL, 9 SSL, 9 MX) with HP, ROC in lb for loaders and operating weight in lb for excavators, classes as on the sheet (<2000 and 3500 & Over written the macro's way). 3 rows carry `REVIEW:` in Notes: T550, T62 and T740, with blank figures on the sheet. It loads with 0 warnings. Its Size Class column (D2:D500) has a drop-down, and Excel refuses any other entry (a pasted value bypasses Excel's check: Check setup still warns about it). The drop-down lists the classes on the workbook's second tab, **Set-up**: three tables (CTL, SSL, MX; yellow cells) seeded with the 17 classes, where you add a class by typing it in an empty cell and remove one by clearing its cell, and a fourth column that shows the drop-down as it stands. Since 2.8 the macro reads the same three tables as its allowed classes, so a class added on Set-up can be picked and is read by the next build; it reads the rows from the first tab, so keep Size Class first. With the Austin sample, eight model groups are not on it and read UNMAPPED until added: T64, T66, T86 (the list has T64-2, T66-2, T86-2), E55, E60, E88, S510, S66.

### 5.5 Inventory by Month tab
- Keeps PRODUCT_TYPE Compact Track Loaders, Mini Excavators and Skid-Steer Loaders (ignoring case and outer spaces; written in that spelling so the formulas and filters match); others are dropped and counted.
- **Units in** table (rows 4 onward): B3 is the month cell (yellow and boxed, formatted as Text so a month picked from the drop-down stays text and is not turned into a date; the drop-down lists the months in the build, from File Format F4 down); one row per MSA (every MSA of either export, alphabetical) with live `SUMIFS` of TOTAL by MSA, product type and the month in B3, a Total column and a bold Total row. The formulas cover the whole detail block, so they ignore the filters: SSL units are shown even when SSL rows are hidden. These are the old **CTL=** and **MX=** figures, as units (sum of TOTAL); open question 2 asks the manager to confirm units on the first real run. Changing B3 recalculates the table; the detail stays filtered to the built month.
- **Detail** (header two rows below the Total row): MSA, PRODUCT_TYPE, MODEL_GROUP, MODEL_NUMBER, INVENTORY_DATE, Month ("August 2026"), TOTAL, ORGANIZATION_NAME, ORGANIZATION_CUSTOMER_NUMBER; sorted by MSA, product type (CTL, MX, SSL), INVENTORY_DATE newest first, export order. ### 5.5a Open Orders by MSA tab (v2.5)
- **The rule.** An open order row is an Order Intake row (any size class; CTL, MX or SSL) whose ORDER_STATUS is `ORDERED` or `Not yet processed`, compared the way Excel's SUMIFS compares text: the whole text, ignoring case, not ignoring stray spaces. The tab sums **SUM(F.ORDERED_QUANTITY)** over those rows (the ordered quantity, not a count of order lines); a quantity that is not a number adds nothing. The source is the Order Intake tab of the same report, not the Open Order export (which stays read and logged only). Hidden rows do not matter: CANCELLED rows are excluded by their status anyway, and SSL rows are counted in the table whatever the filters show.
- **Table 1** (A3 caption, header A4:E4 `MSA, CTL, MX, SSL, Total`): one row per MSA, the same MSAs in the same alphabetical order as the inventory "Units in" table ((no MSA) included). B to D are live formulas, two SUMIFS added together, for example in B5: `=SUMIFS('Order Intake'!$G$3:$G$n,'Order Intake'!$B$3:$B$n,$A5,'Order Intake'!$H$3:$H$n,B$4,'Order Intake'!$E$3:$E$n,"ORDERED")+SUMIFS(... ,"Not yet processed")` over the whole Order Intake block, so the table always agrees with the rows the report holds. E is the row's sum; a bold Total row with a double rule above it closes the table. The SSL column is always there, as in the inventory table.
- **The chart** (two rows under the Total row, 700 x 320 pt): a clustered column chart of B4 to C or D of the MSA rows (not the Total column or row), one bar group per product type (CTL, MX, and SSL only when ShowSSL is TRUE) and one bar per MSA, the legend at the bottom, the value axis titled "Ordered quantity", every bar labelled, Cambria throughout. Bars take the report green first, then grey, blue, rust, purple, light green, light grey and navy, repeating after eight MSAs. Above about twelve MSAs the legend and labels get crowded (Section 7). With no MSAs at all there is no chart, only the note "No MSAs: no chart."
- D1 states the source, the build date, the rule and which product types the chart shows. One page, landscape, no freeze panes, no filter.

### 5.6 Style (set like an engineering report, in green)

## 8. Adding an MSA, changing the layout

- **New MSA:** nothing to do; it is a value in the MSA column. Without an MSA column, add its files named `Order Intake <MSA>.xlsx` and so on.
- **Drop the organisation columns from the inventory tab:** remove ORGANIZATION_NAME and ORGANIZATION_CUSTOMER_NUMBER from the detail header and block in `WriteInventory` (and `INV_EXTRA` in `build_report_reference.py`, `INV_HEADERS` in `check_report.py`).
- **New model:** add a row to the size class workbook (name and size class at least) and build again.
- **Add, remove or rename a size class (v2.8):** edit the tables on the Set-up tab of the size class workbook and build again; no code changes. Rename a class in the Size Class rows too, or they read UNMAPPED. The 17 built-in classes (for a file without a Set-up tab) are `SizeClasses()` in the module and `SIZE_CLASSES` in `build_report_reference.py` (and `BUILTIN_CLASSES` in `make_test_fixtures.py`); `make_size_class_master.py` seeds the Set-up tab from `SIZE_CLASSES`. The checker takes each build's classes from its File Format Table 1.
- **Rename the output:** `OutputFileName`.
- **Change the status order, the style or the columns:** constants and the `StatusRank` / `StatusOrder` functions at the top of the module (and the same constants in `build_report_reference.py` and `check_report.py`).
- **Change which statuses count as open orders** (one place in each of the three files, and the wording that names them): in the module, the criteria `Array("ORDERED", "Not yet processed")` in `WriteOpenOrders` and the matching test `st = "ORDERED" Or st = "NOT YET PROCESSED"` in `BuildLogLines` (with the stray-space test below it); in `build_report_reference.py`, `OPEN_STATUSES`; in `check_report.py`, `OPEN_STATUSES` and the formula it expects in `check_open_orders`. The D1 note, the A3 caption, the File Format item and the Run Log lines name the two statuses; change their text in all three files, then `make_test_fixtures.py` (its `OPEN_STATUSES` and the hand-computed figures).
- **Change the chart colours:** `ChartPalette` in the module and `CHART_PALETTE` in `build_report_reference.py` (eight colours, used in MSA order; the checker does not test colours).

## 9. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| "The report was not built. Fix this on the Config sheet..." | The setup check found problems; each line names the setting or file. Fix them, click Check setup until it says ready, then Build report. Nothing was created. |
| "SizeClassFile is blank / not found / is a web address" | Click Choose size class file... and pick the workbook in File Explorer (a synced SharePoint or OneDrive folder works; an "online only" file must be kept on the device). |
| "The size class file ... has no Name of machine or Size Class column" | The headers are spelled differently. Rename them to one of the accepted headers (Section 5.4). |
| "No MSA column found in ... Type the header name into MSAColumn." | The exports have the MSA column under another name. Type that header into MSAColumn. |
| "MSAColumn "..." is not a header of ..." | MSAColumn is set but that file does not have the column (each file read must). Check the spelling, or leave MSAColumn blank. |
| MSAs look wrong (one MSA named 2026, or everything under one name) | No MSA column was found and the MSA came from the file name. Set MSAColumn. The Run Log's "File" lines say which column each file used. |
| "(no MSA)" rows | Rows whose MSA cell is blank in the export. Fix them in Snowflake if they matter; the Run Log counts them. |
| "Models in Order Intake that are not in the size class file (UNMAPPED until added): ..." | Add those models to the size class workbook before building; otherwise they show as UNMAPPED. |
| UNMAPPED Size Class cells (bold, peach) | The model is not in the size class workbook. Add it, build again. |
| "2 Order Intake files found, all are read" | Two exports of one kind are in the folder and both were merged. Remove the one you do not want if it is an old copy. |
| The total at the top of Order Intake does not change when a filter changes | Calculation is set to Manual on this PC. Press F9, or set File > Options > Formulas > Workbook Calculation to Automatic. The report is saved in Automatic mode, but Excel keeps the mode of the first workbook opened in a session. |
| Some rows seem to be missing | They are hidden by the filters (cancelled orders, skid-steer loaders, other inventory months). Clear the filter on that column. Their counts are in the Run Log ("hidden by the filters"). |
| The table under "Units in" shows zeros | The month in B3 has no inventory rows (or there is no inventory file). Pick another month in B3, or check InventoryMonth. |
| The Open Orders by MSA tab shows zeros | No Order Intake row has ORDER_STATUS ORDERED or Not yet processed (the Run Log says so). If a WARNING says some have "extra spaces", the export padded the status; tell the Snowflake owner, or ask for the statuses to be trimmed in the macro. |
| The Open Orders chart is crowded | Many MSAs: one bar and one label per MSA in each group. Read the table above the chart; ask for the multi-level axis (Section 7, decision 3). |
| `missing column(s) ...` in the Run Log | The export's header names changed. The macro looks for the Snowflake names in Section 5.1 (case-insensitive). |
| "... not a date and left as is (rows ...)" | Those cells hold text that is not a date (for example TBD). They stay as they are and sort last in their group. |
| Buttons do nothing, or a red "Security Risk" bar | Mark of the Web: Properties > Unblock, reopen, Enable Content (Section 2a). |
| Only some buttons, or no boxes, after upgrading | Run ShowOpenOrdersReportConfig once (Alt+F8). |
| Import puts the whole module on one line, or "Expected: end of statement" | The `.bas` lost its Windows line endings. Download it again with GitHub's "Download raw file". |
| "... is open in Excel from ... Close it and run again." / "... is open with unsaved changes" | A file with that name is open from elsewhere, or the old report has unsaved edits. Close or save it, build again. |
| Run Log ends with "WARNING: text dates not in yyyy-mm-dd form ..." | The PC uses day-first dates and some text dates were read with that order. Check those rows against the export. |
| Run Log ends with "WARNING: Excel's filters on the ... tab hid other rows than the rules ..." | The rows shown are right (the macro set them), but Excel's filter criterion did not do what was expected. Send the Run Log and your Excel version so the criterion can be fixed. |

## 10. Security note

The macro only reads the files in the input folder and the size class workbook, writes one new workbook, writes the Last run box on its own Config sheet, and touches nothing else (the setup check creates and at once deletes an empty file `~open-orders-write-test.tmp` in the output folder to prove it can save there). It has no external connections. Review the module in the VBA editor before enabling it, as for any macro.

## 11. No-macro fallback

With Python 3 and openpyxl, the same report:

```
python3 build_report_reference.py "C:\exports\2026" "C:\exports\2026\001. Open Orders - Order Intake - Inventory Analysis By MSA.xlsx" --size-class-file "C:\lists\size-class-master.xlsx"
python3 build_report_reference.py <folder> <output.xlsx> --size-class-file <master.xlsx> [--msa-column MSA] [--inventory-month 2026-08-01] [--show-cancelled] [--show-ssl]
```

It stops with the same problems the setup check would list. To check any finished report: `python3 check_report.py <report.xlsx>` (add `--expected test-fixtures/expected.json` for a fixtures build). To run the macro itself without Excel: `python3 run_macro_libreoffice.py <folder> <report.xlsx> --size-class-file <master.xlsx>` (needs LibreOffice; `--check-only`, `--set KEY=VALUE` and `--v1-config` test the setup check and the upgrade).
